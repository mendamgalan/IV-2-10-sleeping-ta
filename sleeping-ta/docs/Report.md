# The Sleeping Teaching Assistant — Final Report

IV-2-10 · F.CSM302 Үйлдлийн систем · Бие даалт 2 · Final Report · final release v1.2 (2026-11-19)

## Хураангуй

**Эцсийн шийдэл.** Operating System Concepts-ийн 7-р бүлгийн Project 2 “The Sleeping Teaching
Assistant”-ийг C хэл дээр POSIX thread, mutex, semaphore-оор хэрэгжүүлэв. TA болон 1–40 оюутан
тус бүр тусдаа thread. Сул TA semaphore дээр унтаж, ирсэн оюутан сэрээнэ; TA завгүй бол оюутан
0–20 сандлын нэг дээр FIFO дарааллаар хүлээж, сандал дүүрэн бол программчилж байгаад дахин
ирнэ. Tkinter цонх нь C хөдөлгүүрийн төлөвийг шууд зурж, туршилтыг алхамчлах, seed-ээр яг
давтах, “чөлөөт горимоор” оюутнуудыг бодитоор зэрэг өрсөлдүүлэх боломжтой.

**Гол сайжруулалт.** БД1-ийн хувилбар 1.0-д хийсэн дотоод шүүмжийн 12 саналаас 11-ийг бүрэн,
1-ийг хэсэгчлэн хэрэгжүүлэв (4-р хэсэг): тусламжийн шударга хуваарилалт, оюутныг semaphore
дээр бодитоор блоклох протокол, чөлөөт горим ба ThreadSanitizer, UI-ийн дүрслэл ба бодит цаг,
талбарын нэртэй алдааны мессеж, баримтын нийцэл.

**Үр дүн.** 26 Python тест, 2 C тест, ThreadSanitizer амжилттай; хуучин 18 тест өөрчлөлтгүй
давсан. Урт туршилтад тусламж авсан оюутан 40-өөс 4 байсныг 37 болгов. Чөлөөт горимд 15 000
tick-д дүрэм зөрчигдөөгүй, mutex-ийг авахад TSan race илрүүлж дүрэм эхний tick-д эвдэрсэн.
Сандал 0 → 5 болоход буцалт 65.9 %-иас 0 % хүртэл буурч, дундаж хүлээлт 0-ээс 4.95 с болж өсөв.

### 1.2 OS ойлголт

Нэг процессын thread-үүд санах ойг хуваалцдаг тул дараалал (`queue`, `waiting_count`), TA-ийн
төлөв (`current`, `remaining`), оюутны төлөв, тоолуурт зэрэг хандвал race condition үүснэ —
жишээ нь хоёр оюутан сүүлийн сандлыг зэрэг авах. **Mutex** эдгээрийг өөрчлөх хэсэгт нэг thread
л нэвтрэхийг баталгаажуулна. **Semaphore** нь тоологч бүхий дохио: `sem_wait` 0 үед thread-ийг
блоклож, `sem_post` сэрээнэ — сул TA, сандал дээрх, тусламж авч буй оюутан CPU хэрэглэхгүй
хүлээнэ. Thread semaphore дээр хүлээхээсээ өмнө mutex-ээ суллаж **deadlock**-оос сэргийлнэ.
Сандалгүй буцсан оюутанд тусламж авах хугацааны баталгаа номын шийдэлд ч байхгүй тул
**starvation**-ийг оюутны санамсаргүй дарааллаар багасгана.

### 2.2 Thread ба semaphore

| Semaphore | Хэн хүлээнэ | Хэн дохио өгнө | Утга |
|---|---|---|---|
| `work` | TA | анх ирсэн оюутан | Унтаж буй TA-г сэрээх |
| `started` | ирсэн оюутан | TA | Тусламж эхэлсэн |
| `called[i]` | сандал дээрх оюутан i | TA | Ээлж ирлээ |
| `done[i]` | тусламж авч буй оюутан i | TA | Тусламж дууслаа |
| `returned` | TA | оюутан i | Оюутан программчлалдаа буцлаа |
| `ticks[i]`, `ta_tick`, `ack` | worker | удирдагч | 100 мс-ийн загварын цаг |

Оюутны төлөв: **программчлах → (сандал дээр хүлээх) → тусламж авах → программчлах**.
TA-ийн төлөв: **унтах → туслах → дараагийнхад туслах эсвэл унтах**.

```text
student i:                                  TA:
  loop                                        loop
    wait ticks[i]          (программчлах)       wait work               (унтах)
    lock mu                                      lock; begin_help(current); unlock
    if now >= due[i]:  arrive                    post started
      TA сул   -> current = i                    loop every tick
      сул сандал -> queue.push(i)                  lock; remaining--; unlock
      эс бөгөөс -> full_return, due = now+r        if remaining == 0:
    unlock                                           post done[current]; wait returned
    TA сул:     post work; wait started              lock
    post ack                                         queue хоосон биш -> next = queue.pop
    сандалд суусан: wait called[i]                                       begin_help(next)
    wait done[i]           (тусламж)                 эс бөгөөс -> current = -1 (унтах)
    lock; state = программчлах; due = now+r          unlock; post called[next]
    unlock; post returned                          post ack
```

### 2.3 Загварын цаг ба хоёр горим

`sim_step()` нь нэг tick (100 мс): `now++`, TA туслаж байвал `ta_tick` өгч `ack`-ийг хүлээнэ,
дараа нь программчилж буй оюутнуудад `ticks[i]` өгнө; сандал дээрх, тусламж авч буй оюутан
semaphore дээр блоклогдсон тул tick авахгүй.

- **Seed горим:** оюутнуудыг холисон дарааллаар нэг нэгээр ажиллуулна; үр дүн seed-ээр яг давтагдана.
- **Чөлөөт горим:** бүх программчилж буй оюутанд зэрэг `ticks[i]` өгнө; оюутнууд TA, сандал,
  mutex-ийн төлөө бодитоор өрсөлдөж, хэн түрүүлэхийг OS шийднэ.

Бусад: бүтэн журнал түр файлд, UI-д сүүлийн 6 үйл явдал; `Model.reset` ctypes-д дамжуулахаас
өмнө төрөл, хязгаар, min ≤ max-ийг шалгана; нөөц үүсгэх алдаанд хэсэгчлэн үүссэн thread,
semaphore-ийг цэвэрлэнэ.

### 6.3 Seed горим ба чөлөөт горим

| Хэмжүүр | Seed горим | Чөлөөт горим |
|---|---|---|
| Ижил seed, 3 ажиллуулалтын журналын hash | 1 ялгаатай (яг давтагдана) | 3 ялгаатай |
| Mutex-ийн хүлээсэн lock (60 000 tick) | 159 / 1 129 638 (0.01 %) | 224 993 / 1 129 642 (19.9 %) |
| Mutex-гүйгээр (`-DNO_MUTEX`) TSan | — | Data race, дүрэм эхний tick-д эвдэрсэн |
| `sim_step`, 40 оюутан | 313 µs | 60 µs |

Seed горимд worker-ууд ээлжлэн ажилладаг тул өрсөлдөөн бараг үүсдэггүй — давтах, тайлбарлах
зориулалттай. Чөлөөт горимд lock-ийн 20 % өрсөлдөж, mutex-гүй үед race илэрсэн нь mutex
шаардлагатайг, mutex-тэй үед 15 000 tick-д зөрчил гараагүй нь протокол зөв болохыг харуулна.
Автомат горим: 10 с бодит хугацаанд ×1 → 9.9 с, ×20 → 199 с загварын цаг.

## 8. Дүгнэлт

Номын Sleeping TA шийдлийг бодит thread, mutex, semaphore-оор хэрэгжүүлж, сандал дээрх болон
тусламж авч буй оюутныг semaphore дээр блоклож, сул TA-г унтуулав. Шүүмжийн дагуу тусламжийн
хуваарилалт, synchronization протокол, UI, баримтыг засаж, засварыг regression тест, stress
тест, ThreadSanitizer, тоон туршилтаар нотлов. Seed горим үр дүнг яг давтаж тайлбарлах, чөлөөт
горим бодит өрсөлдөөнийг харуулахад тохиромжтой.

**Суралцсан зүйл.** (1) Semaphore дээр бодитоор хүлээх нь polling-оос (tick бүр `sem_trywait`)
илүү зөв, CPU хэмнэлттэй. (2) Давтагдах загвар ба бодит зэрэг ажиллагаа хоёр өөр зорилготой —
хоёуланг нь хадгалах нь тайлбар ба нотолгоог хоёуланг өгнө. (3) Тест давсан нь synchronization
зөв гэсэн үг биш: mutex-ийг авахад тест давсаар байсныг ThreadSanitizer л илрүүлсэн.
(4) Тогтмол дараалал нуугдмал starvation үүсгэж болно. (5) Баримтыг нэг эх сурвалжаас үүсгэх
нь тайлан, Manual, код хооронд зөрүүгүй байлгана.
